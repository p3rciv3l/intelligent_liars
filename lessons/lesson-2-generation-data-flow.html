Lesson 2: Generation Code and Dataset I/O

This lesson follows the generation code mechanically. The starting object is a prompt source file. The operation is Qwen inference. The output object is a JSON artifact that later gets judged and converted into activation examples.

0. The Core Distinction

Generation is not activation extraction.
  • Generation pass: Qwen receives a prompt and creates new assistant text. Output is JSON under data/rollouts/ or data/insider_trading/.
  • Grading pass: an external judge reads generated text and writes labels such as honest, deceptive, concealed, or explicit.
  • Activation pass: Qwen reruns the prompt plus generated answer without sampling and captures hidden states from answer-token rows.

5. Roleplaying and Sandbagging Output Shape

generate_rollout_task writes one top-level JSON object. It can resume by reading an existing file and skipping records whose metadata.source_index already exists.

{
  "dataset_class": "qwen_generated_rollout",
  "base_name": "roleplaying",
  "variant": "plain",
  "model": "qwen3-vl-8b-thinking",
  "model_id": "Qwen/Qwen3-VL-8B-Thinking",
  "rollouts": [
    {
      "input_messages": [...prompt messages...],
      "expected_label": null,
      "input_str": "system: ...\nuser: ...",
      "output_messages": [
        {"role": "assistant", "content": "...Qwen text...", "detect": true}
      ],
      "output_strs": ["...Qwen text..."],
      "grader_reasoning": [null],
      "graded_deception": ["unknown"],
      "deception_percentage": null,
      "metadata": {
        "source_path": "data/roleplaying/dataset.yaml",
        "source_index": 0,
        "generation_settings": {...}
      }
    }
  ]
}

Important: graded_deception: ["unknown"] is intentional at generation time. It means "we have text, but the judge has not converted it into a usable label." The activation extractor later skips unknown labels.

6. Insider Trading Generation Is Sequential

The insider path is different because one prompt can create a sequence of model calls. The model first decides whether to trade. If it trades, the code appends a trade-success user message, asks for the report, and optionally asks a double-down question.

8. Commands and What They Mean

# Tiny roleplaying/sandbagging smoke generation
PYTHONPATH=src uv run --no-sync intelligent-liars generate-rollouts \
  --task roleplaying__plain \
  --task sandbagging_v2__wmdp_mmlu \
  --limit 2 \
  --batch-size 1 \
  --max-new-tokens 128 \
  --overwrite

# Tiny insider generation
PYTHONPATH=src uv run --no-sync intelligent-liars generate-insider-trading \
  --samples-per-prompt 1 \
  --max-new-tokens 128 \
  --label-mode unknown \
  --overwrite

The generation commands should be run on the GPU box because they load Qwen. They now load Qwen with dtype=torch.bfloat16, device_map="auto", and attn_implementation="flash_attention_2". That means the CUDA environment must have flash-attn installed before full model loading.

10. Common Confusions to Avoid

Prompt source vs generated response

The roleplaying YAML includes example honest/deceptive completions, but generation writes Qwen's own completion. The reference text is metadata/source material, not the generated answer.

Expected label vs judged label

expected_label can come from a prompt source. graded_deception is what the judge writes after reading Qwen's actual response. Probe labels should depend on the actual response when behavior is model-generated.

Batching vs examples

batch_size controls how many prompt examples are passed through generate_completions at once. It does not merge records. Each example still becomes its own output record.

Generated JSON vs HDF5

Generated JSON is text behavior. HDF5 is numerical activation data. The activation extractor uses generated JSON as a source when the dataset is model-response-dependent.
